# Cleanup phase: delete App CR and Chart CR after successful migration

After `MonitorHelmRelease` succeeds, a new **Clean-up** section guides the operator through removing the now-redundant App CR and Chart CR. The behavior branches on whether the App CR is Flux-managed (both `kustomize.toolkit.fluxcd.io/name` and `kustomize.toolkit.fluxcd.io/namespace` labels present).

**Flux-managed path — print only.** The tool cannot delete these objects automatically because the operator must first commit the converted Flux resources to the gitops repository and remove the App CR from it; deleting before that would cause Kustomization to immediately recreate it. The tool prints concrete `kubectl` commands to: remove the finalizer `operatorkit.giantswarm.io/app-operator-app` from the App CR, delete the App CR, remove `operatorkit.giantswarm.io/chart-operator-chart` from the Chart CR, and delete the Chart CR. No live API calls are made in this path — the paused annotations were set earlier in the same run. When the App CR targets a remote workload cluster (`spec.kubeConfig.inCluster: false`), the Chart CR commands are annotated with a note that they must run against the workload cluster, and the MC Secret (`spec.kubeConfig.secret.namespace/name`) containing the kubeconfig is named.

**Non-Flux path — automated with confirmation prompt.** A `y/N` prompt gates the deletion. If confirmed: re-fetch both CRs from the cluster and verify paused annotations (`app-operator.giantswarm.io/paused: "true"` on the App CR, `chart-operator.giantswarm.io/paused: "true"` on the Chart CR); if either is missing, re-apply it rather than aborting — the intent is unambiguous and a missing annotation most likely means it was stripped by an operator tool between steps. Chart CR is deleted first (patch to remove finalizer, then delete, then poll until 404), then App CR the same way. If Chart CR cleanup succeeds but App CR cleanup fails (or vice versa), the tool reports what succeeded and what failed and exits non-zero; no retry. The polling uses `_POLL_INTERVAL_S` / `_POLL_TIMEOUT_S` defined in `migrator/__init__.py` and shared across all migrator submodules.

Cleanup is implemented as a plain function in `migrator/cleanup.py`, not as a `MigrationStep` subclass. It runs after the `MigrationRunner` loop completes and is never pushed onto the runner's revert stack — there is no meaningful revert once the migrated workload is live under Flux.
